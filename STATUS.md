## What this repository is

A runnable companion to the technical appendices of the source artifact. It preserves the original implementation lineage while making technical claims progressively more reproducible, testable, and revisable.

## What this repository is not

- not the canonical TRIA runtime;
- not a production safety system;
- not a clinical or diagnostic system;
- not evidence of machine consciousness;
- not validation of metaphysical or symbolic claims;
- not a substitute for the later Trivian Institute research repositories.

## Hardening direction

1. Preserve the source-derived behavior and provenance.
2. Add tests before changing semantics.
3. Move magic numbers and thresholds into explicit configuration where possible.
4. Label symbolic metadata separately from empirical variables.
5. Record divergences from later TRIA research instead of overwriting history.
6. Add machine-readable outputs and schemas where the source artifact implies structured exchange.
7. Treat later research as a successor/evolution layer, not as permission to erase the original implementation.

## Epistemic rule

A value can be meaningful within the authored Trivian symbolic system without being empirically validated. Code and documentation must preserve that distinction.

## Verification target

The repository is not considered technically hardened until each executable module has:

- a documented invocation;
- deterministic smoke tests where feasible;
- failure-case tests;
- CI across supported Python versions;
- explicit input/output contracts;
- no undocumented dependency on mystical or psychological state inference.
